<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GAFF server -> Stripe | Secret API keys and webhook secrets are server-only and must never leak into client bundles. |
| Stripe webhook -> booking system | External callbacks can be spoofed or replayed; signature verification and idempotency are mandatory. |
| GAFF server -> Resend | Transactional email should only send after trustworthy payment confirmation. |

## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Spoofing | Stripe webhook | mitigate | Verify webhook signatures with the official Stripe library against `STRIPE_WEBHOOK_SECRET` before any side effects. |
| T-03-02-02 | Repudiation | Payment fulfillment | mitigate | Persist Stripe session and payment intent IDs and make webhook handling idempotent. |
| T-03-02-03 | Information Disclosure | Stripe and Resend config | mitigate | Keep secret keys server-only and expose only the publishable key to the browser. |
| T-03-02-04 | Integrity | Boat blocking and confirmation email | mitigate | Perform booking state transition plus availability reconciliation transactionally, and send email only after that succeeds. |
</threat_model>
