## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Protected admin shell -> future-facing admin pages | These sections are admin-only operational views even when they are partially scaffolded, so they still require authenticated access and sensible data exposure. |
| Settings UI -> environment/integration visibility | Configuration and health surfaces can accidentally expose secrets if raw env values are rendered. |
| Review and marketing data -> admin readers | These pages summarize customer-facing communications and should expose only what the schema intends, not hidden raw internals or sensitive tokens. |

## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Information Disclosure | Settings and integration health | mitigate | Show presence/health metadata only, never raw secret values or full credentials. |
| T-04-03-02 | Elevation of Privilege | Future-facing admin sections | mitigate | Keep route access inside the protected admin shell and apply role-aware page visibility consistently. |
| T-04-03-03 | Integrity | Agent status framing | mitigate | Mark unavailable future automation as planned or pending explicitly so admins do not mistake scaffolds for live automation. |
| T-04-03-04 | Information Disclosure | Reviews and marketing surfaces | mitigate | Read from schema-backed summaries and avoid rendering unnecessary raw metadata blobs or unpublished secret config. |
</threat_model>
