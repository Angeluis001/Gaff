## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin route params/search params -> server queries | Search, filter, and pagination inputs are admin-controlled but still untrusted and must be normalized before touching Neon queries. |
| Admin read models -> dashboard UI | KPI cards and tables drive operational decisions, so joins and totals must reflect canonical Phase 3 booking truth. |
| Fleet maintenance controls -> availability records | Admin-side availability changes can block inventory and must not drift from the booking system's day-level model. |

## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Tampering | Search and pagination params | mitigate | Parse and clamp page, filter, and sort inputs server-side before query execution. |
| T-04-02-02 | Integrity | KPI and revenue figures | mitigate | Derive totals from canonical bookings data and document which statuses count toward revenue and occupancy. |
| T-04-02-03 | Information Disclosure | Client and lead detail pages | mitigate | Restrict detail routes to authenticated admin roles and avoid exposing unnecessary raw metadata blobs. |
| T-04-02-04 | Integrity | Fleet maintenance windows | mitigate | Reuse `boat_availability` as the single operational source of truth and avoid parallel admin-only state. |
</threat_model>
