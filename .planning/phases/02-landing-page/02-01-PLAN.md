<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `NEXT_PUBLIC_*` env -> browser | Public IDs and measurement IDs are exposed client-side, but API secrets must stay server-only. |
| Cloudinary media -> landing page | Only transformed CDN URLs may reach the client; API key and secret must never be imported into client code. |
| Scroll and language providers -> root layout | Client wrappers must not force `layout.tsx` itself into a client component. |

## STRIDE Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Information Disclosure | Cloudinary configuration | mitigate | Use `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` only in client-facing code and keep `CLOUDINARY_API_KEY` / `CLOUDINARY_API_SECRET` out of `NEXT_PUBLIC_*`. |
| T-02-01-02 | Denial of Service | Hero media | mitigate | Use Cloudinary auto-format/quality transforms and a poster or gradient fallback so the hero does not force a large eager download. |
| T-02-01-03 | Tampering | `next.config.ts` image policy | mitigate | Restrict `images.remotePatterns` to `res.cloudinary.com` and keep all other remote image hosts blocked. |
| T-02-01-04 | Elevation of Privilege | Root layout wrappers | mitigate | Mount `SmoothScroll` and `LanguageProvider` from `layout.tsx` without adding `"use client"` to the layout. |
</threat_model>
